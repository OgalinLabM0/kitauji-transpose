# 北宇治译奏部 · KitaUji Transpose

日文轻小说翻译与校对工作台，当前公开版本 **0.0.10**。Windows x64，支持 EPUB / TXT 导入、日中对照、术语确认、自动翻译检查和成品导出。

0.0.10 扩大待确认工作区，长候选名称与理由分行，支持逐项处理。新增可收起的中文分析助手：解释原句、比较候选、追问和缓存；建议须人工确认。术语可确认成英文正文＋中文ruby，阅读与导出一致，假名的英文拼写不确定时由用户决定。兼容原有待确认项、稿件和断点，无需清库或重新导入。

0.0.6 改善运行卡顿：任务日志分页显示，完整详情按需读取；后台日志不再带动其他页面整页刷新。准备状态与章节/全册段落查询移入独立只读线程，减少查看进度时窗口被阻塞的问题。原始日志、书库、设置和翻译标准保留。

0.0.5 修复姓名拆成名和姓后被术语筛选误排除的问题。当前有效人物资料与本册原文能对应的假名姓名组成词会保留待确认，初提遗漏的组成词也会补齐；不因人物页已有人物就跳过译名确认。旧机器排除可按有效依据恢复，但不会重复恢复重新提取的同名候选，也不替用户选择中文。术语准备规则更新后，继续任务会重新核对术语准备，已有稿件保留并按新确认译名复查。

本版也修复旧引文造成的自动修复停滞：当旧稿已被修改，独立复核确认问题仍在时，会将当前稿的准确引文与原因交给有限次数的修复流程。原稿、旧诊断和检查仍保留；不确定的问题不会自动放行。

0.0.4 修复短平假名等真实姓名被当作泛称丢弃的问题：只有原文与独立核对记录都有效时才保留。已核对的本册假名姓名会补入术语候选并继续筛选，译名仍由用户确认，汉字人名仍不进入术语确认。原有稿件、书库和成功进度保留；不会自动重跑已经完成的章节。

0.0.3 新增姓名边界独立核对：陌生职衔紧接姓名时，先根据原文核对人物身份类别，减少程序误拒。不能确认归属的姓名建议保留供核对，既有成功预读进度继续有效。这不保证模型绝不漏提姓名或任意书籍零错误。

0.0.2 改进双语 EPUB 识别与已有中文隔离，并加入后台任务进度、预读失败自动缩小批次、人物属性独立核对和章节问题自动修复。网络、接口限额或无法自动解决的问题仍会保留进度并暂停；术语最终译名仍由用户确认。

## 下载与开始

在 [Releases](https://github.com/OgalinLabM0/kitauji-transpose/releases) 下载 Windows 免安装包，完整解压到可写目录，再运行 **北宇治译奏部.exe**。不要只复制 exe。

1. 在设置中填写自己的 API 地址和密钥，保存并测试连接。
2. 导入书籍，点击“开始翻译”，选择成品保存位置。
3. 系统自动预处理；出现术语时由你确认最终译名，再继续翻译、检查和保存。遇到无法自动解决的问题会保留进度。

主界面可切换日中对照、只读中文和全册连读。重要术语不会由软件擅自替你确定。

## 双语 EPUB

支持相邻段落中日交替，中文在前或日文在前均可，同一 XHTML 文件方向保持一致。日文使用行内 `opacity:0.4`，或通过 `lang` / `xml:lang` 标记为 `ja`、`ja-JP`；对应中文可以不标语言，也可标为 `zh`、`zh-CN`。这不是任意双语排版的自动识别器；具体结构和限制见 [双语 EPUB 导入说明](docs/使用/双语EPUB导入.md)。

已有中文只在“对比已有译文”中供你查阅，不成为待译原文，也不发送给预读、术语、翻译或检查模型。在已识别的双语书中，未标语言且不属于配对正文的附页只保留原样，不交给模型；因此成品可能保留这些原书附页。

旧版已经按混合原文导入的书不会被自动覆盖。请先备份，再删除并重新导入这一册，无须清空整个书库。

## 模型与质量

当前策略针对 **DeepSeek 官方 API / deepseek-flash** 验证。正文初译、编辑和关键审校使用 high；局部表达、预处理、版式、对齐和章节连读等使用 disabled。程序按实际工位自动选择，每次调用的模型与思考配置可在运行记录中查阅。

第三方兼容接口没有经过同等实验，不能保证执行相同的思考设置。软件以忠实原文、保留人物声音和自然读感为目标，但不保证任意作品零错误或所有译文都达到专业出版水准。保存前可查阅问题与日中对照。

运行 AI 功能会将相关原文、上下文和已确认资料发送到你配置的服务商，并消耗该接口的用量。

## 数据与密钥

- 默认书库、设置、日志、缓存和程序临时文件放在 exe 旁的 `data` 中。
- 设置 → 数据位置 → **选择目录并重启**，可改到其他空文件夹。重启后复制并核验数据，成功才切换；旧目录保留作备份。正在运行任务时请先停止或等待完成。
- 程序旁的 `data-location.json` 仅记录路径。使用自定义位置时，移动程序仍会访问该位置；使用默认位置时请连同 `data` 移动。
- 目录不可写会明确报错，不会静默改用 C 盘。建议直接解压到自己可写的 D 盘目录。
- 完整 API 密钥由 Windows 加密保存，日志只显示脱敏尾四位，如 `****AB12`。跨电脑后可能需要重新填写密钥。
- 更新时保留自己的 `data` 和 `data-location.json`，替换程序文件前关闭软件。

## 开发

需要 Node.js 22.12+ 和 npm；Windows 桌面包在 Windows 上构建。

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run package:dir
```

开发预览：先运行 `npm run dev:renderer`，再在另一终端运行 `npm run dev`。浏览器静态预览为 `npm run dev:preview`，不操作正式书库。

提示规则真源为 `docs/标准/TRANSLATION_RULES.md`，构建时自动生成工位规则。公开测试覆盖数据目录、安全迁移及合成双语书的导入、隔离和导出；内部含私人书稿的翻译质量实验、原始素材及开发记录未上传，公开测试不代表整书翻译质量证明。

本版附带免安装 ZIP；安装器、自动更新和跨电脑密钥迁移不在本版验证范围。

0.0.10增加有原文依据的人物称谓关联补全；仅全半角不同的术语合并确认、统一译法并支持整组撤销。证据不足仍保留提醒，不自动猜测人物或替用户确认译名。
